How it works

  
Three steps, and a dry run so nothing happens until you say so.

  

    
Write a plan
Headings are epics. Bullets are tickets. A size like (M) becomes story points.

    
Dry run
See how many epics and tickets it found. Nothing is written to Jira.

    
Apply
Epics and stories are created and linked. Re-runs skip what exists, so there are no duplicates.

  






  
Quick start

  
Node 22 or newer. Nothing to install.

  

    
1. Get the code


git clone https://github.com/Ritesh-Dhekane/md2jira
cd md2jira

    
2. Create an API token

    
Open id.atlassian.com → Security → API tokens, choose Create API token (not the scoped variant) and set a short expiry.

    
3. Add credentials


# .env  (git-ignored)
JIRA_EMAIL=the-email-you-log-into-atlassian-with
JIRA_TOKEN=the-token

  

    
4. Add a config file


// md2jira.config.json
{
  "site": "your-team.atlassian.net",
  "project": "ABC",
  "epicType": "Epic",
  "ticketType": "Story",
  "points": { "S": 1, "M": 2, "L": 3 }
}

    
5. Run it


# dry run: prints what it would create
node bin/md2jira.mjs plan.md

# real test: a couple of issues
node bin/md2jira.mjs plan.md --apply --only "Storefront" --max 2

# everything
node bin/md2jira.mjs plan.md --apply

  

  
The token is read only from the environment or .env. Keep .env out of version control.






  
Plan format

  
Plain Markdown. Anything the parser does not recognise is ignored.


## Storefront (3 days)
Goal: visitors can see the menu.

- **Menu page (M).** Show each drink with a price.
  - AC: every drink has a price.
  - AC: the page works at phone width.
- **Map and hours (S).** Embed a map.

---

## Notes
Sections without tickets are skipped.

  

    
MarkdownBecomes

    
## Title (3 days)An epic. A trailing (N days) is dropped.

    
First plain line under itThe epic description (Goal: is stripped).

    
- **Title (M).** textA story under that epic. M becomes points if it is a key of points.

    
  - AC: …An item in the "Acceptance criteria" list.

    
---Ends the current epic.

  






  
Options

  

    
OptionMeaning

    
--applyActually create the issues. Without it nothing is written.

    
--only "text"Only the epic whose title is, or starts with, the text as whole words. E1 does not match E10.

    
--max NStop after creating N issues.

    
--fix-pointsAlso set story points on tickets created by an earlier run.

    
--config fileConfig path. Default md2jira.config.json in the current folder.

    
--state fileWhere created keys are remembered. Default .md2jira-state.json.

  






  
FAQ

  
Team-managed or company-managed spaces?
Both work. Stories are linked to their epic with the parent field.

  
Why are my story points empty?
If the story-points field is not on the create screen, points are set right after creating. If Jira refuses that too, add the field to the issue layout of the work type, then run again with --fix-points.

  
Will a re-run create duplicates?
No. Created keys are saved in the state file and skipped. Edits to a ticket that already exists are not pushed to Jira.

  
Where does my token go?
Only into your environment or a local .env. It is never written to the config or state files.
